# 规则与生命周期

| 层级 | 证据与范围 | 处理 |
| --- | --- | --- |
| L1 | ~/.workbuddy/logs/YYYY-MM-DD 下直接包含的 workbuddyMainThread__<32位十六进制>.log，目录日期及修改时间均早于保留期截止日期（面板默认 7 天，命令行默认 14 天） | 精确文件计划、关闭应用、移动到废纸篓 |
| L2 | 已由应用标识、版本及成功升级日志匹配的旧应用回退备份 | 优先报告，用户核对新版可用且不需要立即回退，退出 WorkBuddy 和更新程序后，在本地面板勾选并确认，将对应旧应用包移入废纸篓 |
| L2 | traces、cache（含 conversation-product-spill）、clipboard-images 和原生包缓存 | 只看体积，保留现场以核验格式、引用及重建行为 |
| L3 | projects、blobs、file-history、artifact-index、workspace、~/WorkBuddy 等 | 保留会话及产物关联；用户指定项目才建立人工清单 |
| L4 | binaries、plugins、安装包、数据库、应用支持目录及未知项 | 只盘点，禁止脚本处置 |

对项目中间文件记录原路径、占用、生成来源、关联会话、最终产物与是否被代码、页面或附件引用。无法确认时保持原位。禁止依靠扩展名或日期推断可删除。新规则先拿出来源证据，在临时样本验证排除项及恢复，再发版。

扫描按分配块统计，同时提供逻辑字节；同 inode 去重，APFS 克隆和快照可能使统计与可用空间变化不同。报告按客户端本地时区统计创建日期。复制本地数据库及存在的 WAL，在临时副本上只读查询时间与删除标记，复制期间发生变化则停止统计；数据库不可读时显示原因。日期工作区独立列出，不能用目录数推算会话数。

执行前核对 SHA256、日期、进程、边界、链接、文件身份与元数据。只移动单链接普通文件，拒绝跨卷。每次移动前先向废纸篓批次目录写入恢复映射。执行期间保持客户端关闭，避免并发写入或重启。发生部分失败时停止，按映射检查实际位置，下一次执行须重新扫描。

恢复时退出 WorkBuddy，打开废纸篓中的批次文件夹，将对应日志移回映射中的原目录。原路径已经存在时保留两个副本并人工核对，禁止覆盖。清空废纸篓前检查该批次中实际存在的文件。

发布自审覆盖元数据校验、临时数据扫描、路径与链接边界、改动后失效、活跃进程阻断和废纸篓映射；实机只做只读试跑，平台导入单独验证。

复扫时对比同一路径分配空间及文件数。先单列安装包、在用运行时和升级备份，再比较日志、追踪和会话工作区。同一修改日期中的占用仅是当前快照，保留多次扫描才能衡量净增长。运行时先核对已安装版本与进程使用证据。会话目录中的 modify_backup_v2 可能服务于回滚，审阅时明确移走它可能影响哪些恢复操作。

面板仅监听环回地址，要求随机链接、来源和一次性表单确认。备份移动前重跑识别规则并检查目录身份，日志执行前核对保留期与单文件身份。默认保留近期日志用于崩溃、升级回溯和工单复现。面板仅将已确认命名的主线程日志纳入规则，崩溃、迁移、审计及未知日志单列观察。

面板只为数据库状态为 completed 的会话展示结构可识别的 modify_backup_v2。每项显示目录和体积，需逐项勾选确认。移动前重新核对会话状态和目录树身份，链接、跨卷和特殊文件不纳入。恢复时按批次映射移回整个目录，若原路径已重建则暂停并人工核对。
